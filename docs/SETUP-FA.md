# راه‌اندازی محلی B-lock

با Docker Compose، فرانت‌اند Next.js، بک‌اند PHP 8.4 و پایگاه دادهٔ MySQL 8.4 با هم اجرا می‌شوند. فقط وب‌سایت روی کامپیوتر شما پورت باز می‌کند. برای ساخت اولیه اینترنت لازم است. بعد از آن می‌توانید کانتینرهای موجود را اجرا کنید و مقاله‌های همراه پروژه را آفلاین بخوانید.

## ۱. آماده‌سازی سیستم‌عامل

| سیستم‌عامل | نصب و اجرای Docker |
| --- | --- |
| Ubuntu 24.04 LTS و جدیدتر | اگر از بسته‌های خود اوبونتو استفاده می‌کنید، به‌ترتیب `sudo apt update`، سپس `sudo apt install docker.io docker-compose-v2` و بعد `sudo systemctl enable --now docker` را اجرا کنید. اگر Docker را قبلاً از مخزن رسمی خودش نصب کرده‌اید، همان نسخه و افزونهٔ Compose آن کافی است. |
| سایر توزیع‌های لینوکس | Docker Engine و افزونهٔ Compose را طبق [دستور نصب توزیع خود](https://docs.docker.com/engine/install/) نصب کنید و سرویس Docker را اجرا کنید. |
| Windows 10/11 | [Docker Desktop برای ویندوز](https://docs.docker.com/desktop/setup/install/windows-install/) را نصب کنید. WSL 2 و کانتینرهای لینوکسی را فعال کنید، Docker Desktop را باز کنید و دستورهای بعدی را در PowerShell اجرا کنید. |
| macOS با پردازندهٔ Intel یا Apple silicon | [Docker Desktop برای مک](https://docs.docker.com/desktop/setup/install/mac-install/) را متناسب با پردازنده نصب و اجرا کنید. دستورهای بعدی را در Terminal بنویسید. |

اجرای Docker را بررسی کنید:

```sh
docker version
docker compose version
```

دستور اول باید اطلاعات Client و Server را نشان دهد. در لینوکس اگر دسترسی به سوکت Docker ندارید، ابتدای دستورهای Docker در این راهنما `sudo` بگذارید. نصب جداگانهٔ PHP، MySQL یا Node.js لازم نیست. بک‌اند از PDO استفاده می‌کند و به Composer وابسته نیست.

## ۲. باز کردن پروژه

ZIP را استخراج کنید و ترمینال را در پوشه‌ای باز کنید که فایل `compose.yaml` در آن است. اگر Git نصب دارید و به مخزن دسترسی دارید، می‌توانید به‌جای استخراج ZIP این دو دستور را اجرا کنید:

```sh
git clone https://github.com/mmdreza2345/Blog-Project.git
cd Blog-Project
```

## ۳. شروع و بررسی برنامه

```sh
docker compose up --build -d
docker compose ps
```

در اجرای اول، Docker ایمیج‌ها را می‌گیرد، وب‌سایت را می‌سازد و جدول‌ها و داده‌های نمونه را در MySQL وارد می‌کند. وقتی وضعیت `db` به `healthy` رسید و `api` و `web` در حال اجرا بودند، <http://localhost:3000> را باز کنید. در **Articles** نمونه‌ها را ببینید یا با **Sign up** حساب بسازید. اگر مقاله‌ای را با **Save draft** ذخیره کنید، در داشبورد خودتان می‌بینید. وقتی وضعیتش را به **Published** تغییر دهید و ذخیره کنید، در فهرست مقاله‌ها هم ظاهر می‌شود.

تصاویر نمونه همراه پروژه هستند. برای مقالهٔ جدید می‌توانید کادر تصویر را خالی بگذارید تا تصویر دسته‌بندی استفاده شود، یک مسیر موجود مثل `/images/react.png` بدهید یا آدرس HTTPS وارد کنید. نمایش تصاویر خارجی به دسترسی مرورگر به میزبان آن تصویر نیاز دارد.

## دستورهای روزمره

| کار | دستور |
| --- | --- |
| توقف برنامه و نگه داشتن حساب‌ها، مقاله‌ها و پیام‌ها | `docker compose down` |
| اجرای دوباره | `docker compose up -d` |
| اعمال تغییرات کد بعد از ویرایش PHP یا فرانت‌اند | `docker compose up --build -d` |
| مشاهدهٔ رخدادهای اخیر سرویس‌ها | `docker compose logs --tail=60 web api db` |

MySQL داده‌ها را در یک volume به نام `blog_data` نگه می‌دارد. هر همکار کد مشترک را از GitHub می‌گیرد و روی کامپیوتر خودش پایگاه دادهٔ جداگانه دارد. فایل‌های SQL فقط هنگام ساخت پایگاه خالی اجرا می‌شوند. ساخت مجدد برنامه اطلاعات ثبت‌شده را حفظ می‌کند. حذف volume پایگاه داده آن اطلاعات را پاک می‌کند. نشست‌های PHP داخل کانتینر API نگهداری می‌شوند و بعد از ساخت مجدد آن، ممکن است لازم باشد دوباره وارد حساب شوید.

## خواندن پیام‌های تماس

بعد از نمایش پیام موفقیت، اطلاعات در جدول `contact_messages` ذخیره شده است. برای خواندن پیام‌ها با کاربر برنامه وارد MySQL شوید:

```sh
docker compose exec db mysql -u blog -p block_blog
```

رمز نمونهٔ پایگاه داده `local-portfolio-db` است. اگر `BLOG_DB_PASSWORD` را خودتان تنظیم کرده‌اید، همان مقدار را بنویسید. سپس در محیط MySQL اجرا کنید:

```sql
SELECT created_at, name, email, subject, message
FROM contact_messages
ORDER BY id DESC;
```

با `exit` از محیط MySQL خارج شوید. خواندن بازخوردها به دسترسی پایگاه داده نیاز دارد. این نمونه پیام‌ها را در پایگاه محلی نگه می‌دارد و ارسال ایمیل ندارد.

## رفع مشکلات راه‌اندازی

- **پورت ۳۰۰۰ اشغال است.** کنار `compose.yaml` یک فایل `.env` بسازید و داخلش `BLOG_PORT=3100` بنویسید. دوباره `docker compose up -d` را اجرا کنید و <http://localhost:3100> را باز کنید.
- **Docker پاسخ نمی‌دهد.** Docker Desktop یا سرویس Docker Engine را اجرا کنید و خروجی `docker version` را بررسی کنید.
- **سایت خطای سرویس می‌دهد.** ابتدا `docker compose ps` و سپس `docker compose logs --tail=60 api db` را بررسی کنید. برای اجرای اول صبر کنید سلامت دیتابیس تأیید شود. مرورگر از مسیر `/api` روی آدرس خود سایت به PHP دسترسی دارد.
- **در لینوکس MySQL برای پوشهٔ SQL خطای دسترسی می‌دهد.** در ریشهٔ پروژه `chmod a+rx database` و سپس `chmod a+r database/*.sql` را اجرا کنید و سرویس‌ها را دوباره بالا بیاورید. این پوشه شامل ساختار جدول‌ها و مقاله‌های نمونه است.
- **رمز دلخواه برای پایگاه داده می‌خواهید.** قبل از اولین اجرا مقدار `BLOG_DB_PASSWORD` را در `.env` محلی تعیین کنید. اگر volume از قبل ساخته شده، تغییر این فایل به‌تنهایی رمز کاربر MySQL را عوض نمی‌کند. مقدار قبلی را حفظ کنید یا هم‌زمان رمز آن کاربر را در MySQL تغییر دهید.
- **ورود با حساب نمونه ممکن نیست.** یک حساب تازه ثبت کنید. نویسندهٔ تحریریه فقط برای مقاله‌های اولیه است و رمز ورود ندارد. هر کاربر مقاله‌هایی را مدیریت می‌کند که با حساب خودش ساخته است.
